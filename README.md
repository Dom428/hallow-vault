# Hallow Vault

Backs up your game saves and settings, and (1.16) the whole Hallow family - part of the Hallow family with [Hallow Hub](https://github.com/Dom428/hallow-hub), [Hallow Mixer](https://github.com/Dom428/hallow-mixer) and [Hallow Toolkit](https://github.com/Dom428/hallow-toolkit).

- **Finds your saves by itself:** Steam's per-game folders (every account on the PC), Unity games (`LocalLow\company\product` from the game's `app.info`), Unreal games (`LocalAppData\<project>\Saved`), a few well-known places, and (1.13) a built-in list of common places: `Documents\My Games\<game>`, `Saved Games\<game>` and `Saved Games\<company>\<game>`, and - for games nothing else finds - `AppData\LocalLow\<company>\<game>`, `AppData\Roaming\<game>`, `AppData\Local\<game>`. Add any folder yourself. **Steam Cloud:** games Steam already syncs (any Steam account on the PC) are marked - Vault keeps its own versions too, since Steam Cloud keeps only the latest.
- **Backs up when a game closes** (only if something changed), **right before Steam updates a game** (the app manifest says an update is waiting or starting) **and once a day**, keeping the last 10 versions per game. Never while the game is still writing: it waits until no save file has changed for 10 seconds.
- **Restore any version** - your current saves are backed up first, every time (a whole version or one file). **Preview** shows which files were added, removed, got bigger, smaller or were saved again, with their sizes and when each was last saved (between two versions, or a version and your saves now), what restoring would do (bring back, overwrite, leave newer files alone - a restore never deletes), and **Restore file** puts back just that one file (1.13).
- Backups are plain **.zip** files, on a second drive by default (or any folder / network share you pick).
- **Second copy** to another folder you pick - a NAS or network share (pick it, or type `\\NAS\share\folder`), a OneDrive, Google Drive or Dropbox folder, or a USB drive (no accounts inside Vault). Every new backup is copied there, read back and compared by **SHA-256** before it counts (a copy that doesn't match is copied again, then reported); the hashes are kept in `sha256.txt` (sha256sum format) in each game's copy folder. Old copies go in step with the vault, or the copy keeps **its own number of versions** (newest 5-100 per game; pinned ones always stay). **Verify copies** (Settings, the weekly check, pipe `verify`) reads every copy back again; a damaged copy is replaced from the vault, one the vault no longer has is reported and kept. **Size limits** per game and for the whole vault: oldest versions go first, never a game's newest.
- Leaves out logs, caches, crash dumps and secrets.
- **Hallow family backup (1.16)** - the family's backup hub, behind the **Family backup** button:
  - **What:** every Hallow app's settings folders (`%APPDATA%\Hallow*` and `%LOCALAPPDATA%\Hallow*`, plus the family `theme.json`); **Hallow Keys' encrypted backups** (the dated `*.hkbackup` files from the folder Keys backs up to - read from Keys' `settings.json`) and **Hallow Authenticator's encrypted backups** (`%APPDATA%\HallowAuthenticator\backups` and `\autobackups`, kept by Hallow Remote) as **opaque files**: copied byte for byte (stored uncompressed) and checked by SHA-256 - Vault never opens, parses or decrypts them, and never reads Keys' vault file or Secret Key file at all; optionally **Hallow Clips favourites** (copied once to each destination, not versioned). **Left out:** caches, WebView2 browser data and profiles, Shield's extension build, logs, crash dumps, temp files, programs, Hub's store pictures, Vault's save database cache and secrets (Mixer's API key, Keys' vault and Secret Key file, VPN sign-in); a settings file over 16 MB is left out with a note.
  - **When:** daily, and soon after something changes (looked at every 10 minutes; at most one new version every 3 hours), plus **Back up now**. Each version is one zip `Hallow family yyyy-MM-dd HHmmss.zip` with `family.json` (every file, its app, where it came from, its size and SHA-256), kept as the **newest 14** (7 / 14 / 30 / 60) per destination. Old versions go to the **Recycle Bin** - on a USB drive or a NAS share, where Windows has no Recycle Bin, to a `Removed versions` folder beside them - never deleted for good.
  - **Where:** one or more destinations - another drive (Vault suggests one; never the system drive, Documents, Desktop or Pictures), a USB drive, or a NAS share on your own network (`\\NAS\share`, `.local` / `.lan` names, private addresses 192.168 / 10 / 172.16-31 / Tailscale 100.64-127 only). Each gets `Hallow family backup\<PC name>\`; every copy is read back and compared by SHA-256 before it counts; a destination that's unplugged catches up when it's back. Each shows its free space, last success and last error - including **"Windows' Ransomware protection blocked this folder; pick another or allow Hallow Vault in Windows Security"** with **Allow Hallow Vault...**, which opens Hallow Guard 1.10's Ransomware page (what was blocked and the steps) or, without Guard, Windows Security's *Allow an app through Controlled folder access*. Vault never changes that setting itself.
  - **Restore:** pick a destination and a **date**, then tick **per app**. Settings go back into the app's real folder only once that app is closed: Vault asks it to quit through its family pipe first (and waits up to 15 s; an app that stays open is left alone); every file it replaces is kept in `%APPDATA%\HallowVault\family-restore-safety\`; a restore never deletes files. Keys and Authenticator backups go back as files into the folder that app's own restore uses (never over a file that's there) - you finish in Hallow Keys (Import and export > Restore backup) or on the phone (Hallow Authenticator > Restore from the PC). **Test restore** checks every file of a version against its SHA-256 without restoring anything.
  - **Status:** a quiet note (at most once a day, never while a game runs) when the family backup hasn't worked for 3 days; the main window's summary says when it last ran.
- **Hallow family:** Hallow Hub's game pages show each game's Saves (last backup, Back up now, Restore) and Hallow Remote has Back up now on your phone. The link: Named pipe `HallowFamily.Vault.<user>` (`ping`, `status`, `backup <game>`, `backup all`, `restore <game>` opens the restore window, `check <game>` / `check all` (1.12), `verify` (1.13: re-checks the second copy), `backup-now` (1.16: the Hallow family backup, in the background), `open family` (1.16); current user only), `HallowVault.exe --cmd "backup all"` for scripts and Stream Deck, and `%APPDATA%\HallowVault\status.json`.
- **One Hallow icon:** while Hallow Hub hosts the family tray menu, Vault hides its own icon and its actions (Back up everything now, Restore..., Open the vault folder, Back up when a game closes, and 1.16's Back up the Hallow family now / Hallow family backup...) are in Hub's menu; its messages show from Hub's icon. Pipe commands `open`, `menu`, `invoke <id>`, `quit`. Settings > Use the Hallow icon (on by default); without Hub, Vault keeps its own icon.
- **Hallow accent:** uses the family accent colour from `%APPDATA%\Hallow\theme.json` (picked in Hallow Toolkit), live; Settings > Use the Hallow accent colour.
- **Light and dark mode (1.14):** follows theme.json's `mode` (`dark` / `light` / `system`, written by Hallow Toolkit; missing or unknown = dark), live - `system` follows Windows' app mode (`AppsUseLightTheme`). **Settings > Look:** Follow Hallow (default), Light or Dark just for Vault (wins over the family mode). The light look uses the Hallow family light palette. Title bars follow too. `status` has `look`.
- **Light mode readability (1.15):** same rule as Hallow Toolkit 5.16 - accent text, icons and thin lines are darkened until they reach 4.5:1 on Panel 2 (`#EEEAF5`, so also on the background and white); filled accents (buttons, chips) keep the accent when dark or white text reaches 4.5:1 on it, else a darker fill with white text (violet `#8B5CF6`: white was 4.23:1), hover 0.9 per channel; green / amber status text uses `#1B7A44` / `#8F5B00` (icons and dots keep `#1E8E4F` / `#A66A00`). Windows that are already open (dialogs, What's new, Check backups) recolour in place when the look or accent changes - nothing typed is lost. Dark is unchanged.
- **Crash reports** stay on this PC (`%APPDATA%\HallowVault\crashes`, newest 20; no settings or file contents) with a notice next time; `status` has `lastCrash`.
- **Pins:** pin a version in Restore and it's never pruned or removed by size limits (`pins.txt` next to the zips, copied with the second copy; pipe `pin <game>` / `unpin <game>`).
- **Save alarm:** if a game's saves vanish, empty or shrink under half of the last backup, Vault doesn't back them up over the good ones and tells you (through Hallow Hub's icon when it hosts it), with Restore one click away.
- **Move to a new PC:** Settings > Export copies every game's newest version (and pinned ones) with a manifest to a folder; Import on the new PC restores the ticked games after a safety backup, re-mapping your user folder, Documents, AppData, the Steam account and the game folder.
- **Registry saves:** games that keep saves or settings in `HKCU\Software\<developer>\<game>` (like Unity's PlayerPrefs) are backed up as a `.reg` file inside the zip and put back only into that key, after the usual safety backup.
- **More saves found without a list:** for games nothing else finds, `Documents\<game>` and AppData / LocalAppData / LocalLow folders named after the developer in the game's own files (big guessed folders are ignored as caches).
- **Updates itself** from GitHub releases: asks first and checks the download's SHA-256 (Settings > Check for updates).
- **Schedules and compression:** also back up every 1-12 hours; compression Smallest / Faster / None.
- **Files to back up per game** (right-click a game): include and leave-out patterns like `*.sav` or `Screenshots\*`, with a live count.
- **Backup log** (Settings): every backup, skip, refusal, failure, restore and import with its time, in `%APPDATA%\HallowVault\backup-log.txt`.
- **Second copy you can trust:** Settings shows whether it's up to date, behind or out of reach (USB unplugged), it catches up by itself (on start, every 10 minutes, after backups), and it spots sync conflict copies a cloud app made (`<backup> (1).zip`, `<backup>-PCNAME.zip`, `(conflicted copy)`). `status` has `secondCopy`.
- **Online save database (19,000+ games):** Vault downloads [Ludusavi's manifest](https://github.com/mtkennerly/ludusavi-manifest) from GitHub on first run and re-checks it weekly (re-downloaded only when GitHub's sha changes; a failed or broken download keeps the old copy). A small built-in YAML reader turns it into a cached index in `%APPDATA%\HallowVault\manifest\` (Windows save and settings paths, HKCU\Software keys). Its paths go first; Vault's own finders still add anything it misses. Settings > Online save database.
- **Check backups:** the heart button (all games), right-click a game (just that one) or Settings > Check all now. Every zip must open, each file's own header must be where the zip's table of contents says, every file must match its CRC-32 and size, and - for backups made by 1.12 and newer - the files must match the list Vault records in the zip's `vault.json`. Green / amber (worth a look: no `vault.json`, files Vault didn't list, an unfinished `.part` file) / red (damaged: won't open, cut off, a checksum or size mismatch, a listed file missing) per game, with the reason per backup (also in Restore). Read-only: a check never changes, moves or deletes a backup. Optional weekly check (Settings, off by default) that tells you only when something's wrong. Pipe `check <game>` / `check all`; `status` has `lastCheck` and each game's `check`.
- **Add a game:** back up a game no launcher knows (a DRM-free copy, an emulator, an old game) - a name, its save folder(s) and optionally its `.exe` (Vault then notices that exact program running and backs up when it closes). Stored in `vault.json`, backed up like any other game (daily, every few hours, Back up, the family link), editable any time; its backup folder keeps its name when you rename the game. Removing it only forgets the entry - its backups stay in the vault (add it again with the same name to see them).

### status.json (Hallow Hub, Hallow Guard)

`%APPDATA%\HallowVault\status.json` and the pipe's `status` give the same JSON. Fields only get added, never renamed. Hallow Guard reads `games[].lastBackup` / `off` / `check`, `lastCheck.damaged` and `secondCopy.reachable`; 1.13 adds backup health in one place:

| Field | Meaning |
|---|---|
| `lastBackupAt` | Local time of the newest backup of any game (`yyyy-MM-ddTHH:mm:ss`), or `null` |
| `lastBackupOk` | `true` if the most recent backup try (of a game that's on) made a backup, `false` if it failed or was refused by the save alarm, `null` if none yet. Skips (nothing changed) don't count |
| `failingGames` | `[{ "name", "why" }]` - games (on) whose last backup failed, whose saves look damaged (save alarm), or with a damaged backup in the last check. Empty when all is well |
| `games[].lastResult` | `{ "result": "ok" / "failed" / "refused", "when", "what" }` of that game's last backup try, or `null` |
| `games[].steamCloud` | Steam Cloud also syncs this game |
| `look` | `"light"` or `"dark"`: the look Vault is showing now (1.14) |
| `secondCopy` | `reachable`, `behind`, `conflicts` (1.10) and `path`, `keep` (0 = in step), `verified` (time of the last Verify), `copies`, `mismatched` (1.13); `null` without a second copy |
| `family` | 1.16, the Hallow family backup: `on`, `busy`, `lastBackup` (newest version), `lastRun` (last run that left a destination up to date), `count` (versions of this PC), `files`, `apps`, `sizeBytes`, `keep`, `clips`, `stale` (no run for 3 days), `errors` (`["<path>: <why>"]`), `destinations` (`path`, `kind`, `reachable`, `freeBytes`, `versions`, `lastSuccess`, `lastError`, `blocked` = Ransomware protection) |

Built with the C# compiler that ships with Windows (.NET Framework 4.8): run `build.ps1`. No admin needed.
